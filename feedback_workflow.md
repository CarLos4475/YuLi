# feedback_workflow — Reglas de interacción

## Bugs complejos

Para bugs no triviales: **primero explica el diagnóstico, espera confirmación, luego implementa**. No escribas código hasta que el usuario valide que entendiste el problema correctamente.

Esto evita:
- Correcciones en la dirección equivocada
- Idas y vueltas innecesarias
- Perder tiempo en soluciones que no atacan la causa real
